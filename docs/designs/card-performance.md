# 카드 실적 관리 웹앱 요구사항

- 작성일 2026-11-16
- 상태 확정 (2026-11-16)
- 첫 사용자 본인

## 목표

결제할 때마다 휴대폰에서 가계부에 기록하고, 같은 내역을 데스크톱에서도 확인한다. 카드마다 다음 달 혜택을 받기까지 더 채워야 할 실적과 이번 달에 더 받을 수 있는 예상 할인액을 바로 본다.

## 첫 버전

1. **결제 기록.** 카드, 금액, 가맹점을 입력한다. 결제 시각은 현재 시각이 기본이며 수정할 수 있다. 혜택 판정에 추가 정보가 필요한 경우에만 묻는다. 예를 들어 Youth Club B팩으로 CU에서 결제했다면 KB Pay 사용 여부를 묻는다. 기록을 수정하면 실적과 혜택을 다시 계산한다.
2. **카드별 실적.** 이번 달 인정 실적과 목표까지 남은 금액을 표시한다. 혜택에 따라 실적 기준이 다르면 기준별로 표시한다. 결제 저장으로 목표에 도달하면 그 화면에서 달성 여부를 안내한다.
3. **카드별 혜택.** 혜택 영역마다 이번 달 예상 사용액과 남은 할인 한도를 표시하고, 어떤 결제에 얼마가 적용됐는지 확인할 수 있게 한다. 금액 한도가 없는 캐시백은 이번 달 예상 누계를 표시한다.
4. **월중 시작.** 이미 쌓인 이번 달 인정 실적과 혜택별 사용액을 선택 입력할 수 있다. 생략하면 집계 범위를 ‘기록한 결제 기준’으로 표시한다. 이번 달 혜택 자격 계산에 필요한 전월 실적 정보가 없으면 미확인으로 표시한다.
5. **접근.** 휴대폰과 데스크톱에서 같은 기록을 열 수 있는 반응형 웹앱으로 제공한다. 개인 카드 거래 내역은 가계부 입력을 사용하고, 혜택 계산에는 공개 카드 상품 규칙을 사용한다. 실적 달성 안내는 웹앱 화면에 표시한다.

## 동작 확인 기준

- Youth Club B팩 혜택을 받을 수 있는 달에 CU 오프라인 매장에서 KB Pay로 5천 원을 결제했다고 기록하면 예상 할인액 1천 원과 해당 영역의 남은 한도 1천 원을 표시한다.
- 청춘대로 톡톡카드로 스타벅스에서 간편결제 1만 원을 기록했을 때 두 할인이 적용되는 조건이라면, 각 한도에서 5천 원과 1천 원을 차감하고 실적에는 해당 결제액을 더하지 않는다.
- 실적 목표를 넘기는 거래를 저장하면 저장 화면에 달성 안내가 나온다. 휴대폰에서 저장한 거래를 데스크톱에서 열면 같은 실적과 혜택이 보인다.

## 결정 사항 (2026-11-16)

- **로그인·저장·동기화.** 프론트엔드는 Vercel에 배포하고, 로그인과 데이터 저장은 Supabase(Auth + Postgres)를 사용한다. 휴대폰과 데스크톱은 같은 계정으로 로그인해 같은 DB를 읽는다. EC2를 직접 운영하는 방식은 쓰지 않는다.
- **분류 불명확·취소 거래.** 사용자가 직접 정리한다. 취소 처리한 거래는 실적과 할인 계산에서 모두 제외하고, 관련 실적과 혜택을 다시 계산한다. 가맹점 분류가 불명확한 거래는 사용자가 분류를 정하기 전까지 혜택을 적용하지 않는다.
- **토스뱅크 체크카드.** ‘어디서나’ 적립식으로 다룬다.

## 남은 확인 항목

- 나라사랑체크카드: 블로그 기준 규칙이라 실제 명세서와 다르면 고친다. 빼 둔 규칙(쇼핑 할인, 할인 거래의 실적 포함 여부, 무승인·정부지원금)은 명세서로 확인되면 추가한다.- 기간제 혜택의 적용 및 만료 처리(토스 시즌 종료 등).

첫 확인에는 실제 결제 한 건이면 충분하다. 카드·금액·가맹점만 적어 보고, 그 결제의 실적과 혜택을 판단하려면 무엇을 한 번 더 물어야 할지 확인한다.
